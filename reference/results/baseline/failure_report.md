Map each observed failure mode to the assignment's reliability mechanisms. Use the counts above to prioritise:

- **retrieval_failure** → (G) recovery: rewrite query, switch retrieval strategy, retrieve again. Indicates corpus coverage / lexical mismatch.
- **ranking_failure** → (B) groundedness verification + (F) self-reflection / critic loop: relevant evidence is there but the system can't surface it.
- **partial_recall** → (A) evidence-sufficiency estimation + (B) verifier: we got *some* gold but not enough to ground a confident answer.
- **orchestration_miss** → (G + H) adaptive routing with confidence/trust scoring: a different strategy already had the answer; the router picked wrong. Strong case for a learned policy.
- **ambiguous-by-design** → (D) clarification strategy + (E) abstention. Benchmark notes explicitly flag these as 'should ask for clarification'.
- **out-of-scope (synthesis / grounding / overconfidence)** → demands an answer generator + (B) verifier + (E) abstention + (H) confidence score. These are unobservable in retrieval-only mode but are central to the reliability story we'll build in Steps 2-3.
